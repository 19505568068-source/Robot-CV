# 微信扫码 HR ClawBot

候选人的招聘沟通助理。HR 用微信扫描同一个二维码，在微信内打开独立 H5 对话页；访客同意记录用途后，ClawBot 展示个人介绍并提供原始简历 PDF 下载入口，再基于本机 PDF、DOCX 与文本资料回答问题。聊天按匿名浏览器会话保存，后台提取公司、岗位、招聘条件、关注点与邀约信号，并保留原文证据供候选人复核。

这套方案不接管个人微信，也不要求企业微信主体、CorpID、Secret 或回调配置。它也不需要 MySQL、PostgreSQL 或向量数据库：原始资料保存在本机，状态使用受控 JSON 文件，文档索引只驻留内存。

## 当前实现与部署状态

- 本机管理端和同一局域网内的 H5 访客链路已经完成验证。
- 当前运行环境未配置公网 HTTPS 基址，异地 HR 还不能通过固定二维码访问本机后端。
- `cloudflare-site/` 只是 H5 静态页面；在同源 `/api/public/*` 接入可达的 Node 后端之前，不能称为已完成公网部署。
- 本地分支包含完整前后端源码和 Cloudflare 配置；GitHub/Cloudflare 上的实际版本以远端提交和平台部署记录为准。

## 当前流程

1. HR 扫描后台显示的固定二维码。
2. 页面先展示 AI 身份和聊天记录用途。
3. HR 同意后，系统依次展示候选人介绍、原始简历 PDF 入口，并询问对方来自哪家公司。
4. 收到 HR 第一条回复后，页面展示当前公开的项目与实习标题。
5. HR 点击标题后，ClawBot 说明候选人的角色、具体工作、方法和结果，并请 HR 从该经历开始提问。
6. 后续多轮问题由本机 Codex 根据已授权聊天和命中的知识摘录回答。
7. 后台归档聊天并按邀约意向与岗位匹配度排列机会；结论属于辅助判断，保留原文证据与待确认项。
8. 面试建议、简历改进意见和跟进话术只在候选人点击按钮后生成，具体承诺始终由候选人确认。

## 服务边界

```text
微信扫码 -> H5 访客服务 0.0.0.0:8789
                     |
                     +-> 同意门禁 -> 简历 / 对话 / Codex
                     |
                     +-> 本机 hr.json 机会与聊天存档

候选人浏览器 -> 127.0.0.1:8787 本机管理后台
```

- `8787` 只绑定回环地址，不能从手机或公网访问。
- `8789` 是独立、最小化的访客服务，不提供任何管理接口。
- 未同意的访客不能提交聊天、查看存档或下载简历。
- 二维码中的入口密钥长期保持不变；只有在后台主动点击“更换二维码”后才失效。
- 每次扫码会创建独立的随机会话。状态文件只保存会话和 CSRF 密钥的 SHA-256 哈希。

## 环境要求

- Windows 10/11
- Node.js 22 或更高版本
- 已安装并登录的 Codex CLI：`codex login status`

安装和启动：

```powershell
git clone https://github.com/19505568068-source/Robot-CV.git
cd Robot-CV
npm ci
npm run build
npm start
```

管理后台：`http://127.0.0.1:8787`

启动后，控制台和后台会显示当前访客链接。没有配置公网域名时，系统优先使用电脑的局域网 IPv4，例如 `http://10.x.x.x:8789/e/...`。手机与电脑连接同一局域网后即可测试。

## 首次配置

1. 在“扫码入口”填写候选人显示名称并启用访客接待。
2. 在“对外资料”填写 AI 披露文案和个人简介。
3. 填入原始简历 PDF 的本机绝对路径。
4. 知识库路径可逐行填写 `.pdf`、`.docx`、`.txt`、`.md`、`.json`、`.csv`、`.yaml` 等文件或目录。
5. 保存后，用手机微信扫描二维码完成一次同意、简历下载和问答测试。

原始简历导入后会生成不可变版本，后续的“简历改进意见”不会覆盖原件。当前简历 PDF 会自动加入知识检索，不需要重复填写路径。旧版二进制 `.doc` 不支持，请先另存为 `.docx`；扫描图片型 PDF 首版不做 OCR，请使用可搜索 PDF。

## Codex 隔离

访客消息不会进入普通 Codex 工作区。HR 回答使用单独的 Codex app-server 进程：

- 使用隔离的空工作目录，不读取普通 Codex 工作区；
- 使用独立 `CODEX_HOME`；
- 默认禁用插件、技能、MCP、网页搜索、Shell、文件修改和动态工具；
- 只保留启动隔离会话和读取必要认证配置所需的最小本机权限；
- 只向模型发送裁剪后的候选人资料、文档摘录和已授权聊天；
- 同一访客按独立 Codex 线程保持多轮上下文；
- 超时或失败时发送明确的保底回复，不泄露内部错误。

Responses-compatible API 可在后台作为备用回答源配置，不是 H5 入口的前置条件。API Key 使用当前 Windows 用户的 DPAPI 加密保存。

如需让隔离 Codex 使用兼容服务，可设置 `CODEX_WEIXIN_CODEX_BASE_URL`。该服务会接收经过裁剪的简历摘录与已授权 HR 对话，因此只能配置你明确信任的数据处理方；地址必须是无凭据、查询参数和片段的 HTTPS URL。

## 公网长期入口

当前尚未配置公网 HTTPS 入口，局域网 URL 只适合测试。要让异地 HR 长期扫码，需要把一个固定 HTTPS 域名反向代理到本机 `127.0.0.1:8789`，然后在后台“公网 HTTPS 基址”填写该域名，例如：

```text
https://hr.example.com -> http://127.0.0.1:8789
```

反向代理只开放访客服务，绝不能代理 `8787`。域名和证书保持不变时，同一个二维码可持续使用；电脑上的 Node 服务也必须持续运行。若 Windows 防火墙阻止同一局域网手机访问，需要只为 TCP `8789` 创建专用入站规则，不要开放管理端口。

## 环境变量

```text
CODEX_WEIXIN_PORT         本机管理端口，默认 8787
CODEX_WEIXIN_PUBLIC_PORT  访客端口，默认 8789
CODEX_WEIXIN_PUBLIC_HOST  访客监听地址，默认 0.0.0.0
CODEX_WEIXIN_STATE_DIR    状态目录，默认 %USERPROFILE%\.codex-weixin
CODEX_WEIXIN_OPEN=0       启动时不自动打开后台
CHAT_CODEX_BIN            Codex CLI 路径，可选
CODEX_WEIXIN_CODEX_BASE_URL  可选的 HTTPS Codex 兼容服务基址
CODEX_WEIXIN_CODEX_MODEL    可选的 HR 对话与草稿模型
CODEX_WEIXIN_CODEX_EFFORT   可选的推理强度
```

## 本机数据

```text
%USERPROFILE%\.codex-weixin\
  hr.json                 访客、聊天、机会与本地草稿
  hr-web.json             H5 入口设置和哈希后的会话凭据
  hr-ai.json              可选备用模型配置与加密凭据
  hr-materials\resumes\  不可变简历版本
  hr-codex-runtime\       隔离的 Codex 配置、认证副本与空工作区
```

这些文件包含候选人资料和已授权招聘沟通，不应提交到 Git、同步到公共网盘或交给其他 Windows 用户。修改披露文案会使既有访客重新确认。

## 已知边界

- H5 是微信内网页，不是个人微信好友或公众号聊天窗口。
- 浏览器无法可靠识别微信个人身份，所以“访客”按独立浏览器会话区分；公司和岗位从对话中提取。
- 首版不解析图片型 PDF，也不读取旧 `.doc`。
- 真正的公网长期可用性取决于固定域名、HTTPS 证书、反向代理、电脑网络和 Node 服务持续在线。
- 自动回答不得代替候选人确认面试时间、薪资、Offer、到岗日期或其他承诺。

# HR ClawBot 访客端

这是 HR ClawBot 的微信/H5 访客聊天端静态资源，包含 `index.html`、`app.js` 和 `styles.css`。它依赖 HR ClawBot 的公共访客服务接口（`/api/public/*`），不能单独提供会话、同意门禁、简历下载或 AI 回复。

## 导入来源

资源来自 HR ClawBot 项目的 `src/web-chat`。为避免泄露招聘资料、运行时状态或管理后台，仓库只包含访客端源码，不包含 `hr.json`、简历文件、密钥、`node_modules` 或服务器代码。

## 集成方式

将本目录静态文件部署到 HR ClawBot 的访客服务路径 `/chat/`，或使用项目构建脚本复制到 `dist/web-chat`。访客入口 `/e/<entryToken>` 由 HR ClawBot 服务创建并在首次请求时建立会话。

## 本地预览

直接打开 `index.html` 只能检查布局；接口请求需要由 HR ClawBot 的 `8789` 访客服务提供。

## HR 引导交互

同意后展示简介与简历入口，紧接着询问 HR 来自的公司。公司消息发送成功后，展示可点击的项目/实习标题。点击标题会展开角色、具体工作和提问邀请；后续问题会带上已选经历上下文，通过现有消息接口交给 AI。

部署时同时复制 `candidate-profile.js`。在其中填写候选人确认的公开资料，或让现有会话接口返回 `session.candidateProfile`（优先级更高），结构如下：

```js
{
  introduction: "候选人的真实简介",
  experiences: [
    {
      id: "unique-experience-id",
      type: "project", // 实习使用 internship
      title: "真实项目或实习标题",
      role: "候选人在这段经历中的角色",
      contributions: ["具体负责的工作", "可核实的成果"]
    }
  ]
}
```

每段经历使用唯一 id；缺少标题、角色或具体工作时不显示该卡片。仓库未提供真实履历，因此默认资料为空，不使用虚构经历。未配置简介时优先使用服务端开场消息；没有开场消息则介绍 AI 助理身份。没有经历资料时提示 HR 查看简历并直接提问。

公司信息沿用现有消息接口，以 `我来自的公司：` 为前缀保存，重新载入时从聊天记录恢复。发送失败保留输入，不进入下一步。经历选择仅保留在当前页面；聊天记录仍由服务端保存。原有同意门禁、CSRF 和简历权限保持有效。实际简历内容、AI 回答和消息留存仍需原 HR ClawBot 服务提供。

测试：使用 Node.js 22.13+，执行 `npm ci` 后运行 `npm test`。测试资料仅存在于测试文件，不用于正式页面。
